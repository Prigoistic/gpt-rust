# Fixed-width greedy self-speculation on BLT-1B

The October 26 project charter (v1, §§9 and 18) makes multi-byte generation a parallel workstream. Its first test uses the local decoder to propose several symbols, verifies with the full model, and measures accepted bytes, full and local evaluations, latency, throughput, and output equivalence. This is a single-request, full-prefix implementation of that test on the released checkpoint.

## Procedures

* `probe.py` is the initial control. It recomputes a target anchor each round. Its width includes that anchor, so a width of 8 proposes up to seven additional symbols. Its results are archived separately.
* `fixed_width.py` emits the first target prediction immediately. It drafts up to 2, 4, 8, 16 or 32 **additional** symbols with frozen global conditioning. Each draft step runs the checkpoint's byte hash embeddings, its causal local encoder byte stream, and its local decoder. Drafting skips patch formation, encoder patch pooling/cross-attention and the global transformer. At verification the native entropy patcher and the complete checkpoint run once on the candidate sequence. Commit matching proposals through the first mismatch, then commit the target's correction. If all proposals match, take the bonus prediction within the output limit. Reuse verifier latents for the next draft, keeping decoder assignments through the last predicting position and extending its last visible patch. Future proposals may be wrong. Only target-verified symbols enter the output.
* The width-1 control performs one full call per symbol. All variants produce 40 symbols on each authored prompt and compare the complete ID stream against a separate run of M1's native greedy generator. Warm once per shape and rotate/reverse execution order across three measured repetitions. The five-width sweep covers one English, Python and Hindi prompt each.
* `holdout.py` compares widths 4 and 8 against the unmodified M1 generator on three fresh, longer prompts, generating 64 symbols. Warm once per shape, then run three paired repetitions with rotated order. The external timer includes each complete function call and CUDA synchronization. The native generator transfers its output at the end. The candidate also exposes the first raw byte on the host and constructs the committed ID list. These timings cover local inference without network/queue latency.

The first-byte measurement begins before prompt encoding and ends after the first byte-valued ID reaches the host. In every primary workload the first prediction must be a byte-valued ID. A rendered Unicode character or an entire word may require subsequent bytes. Width affects the block after this first prediction. All results are greedy and fixed-length, using M1's length-aware entropy configuration, fp16 main parameters, fp32 entropy, and unchanged model weights. Each draft byte is still a sequential local decoder evaluation. Peak allocator memory includes the resident models.

## Reproduction

Use the M1 T4 environment, its pinned upstream source and weights, and a configured length-aware JSON as described in the package runbook. Run each script once with `--config PATH --out NEW.jsonl`. Run `python summarize.py fixed.jsonl` for width-sweep metrics. Each result file begins with its run metadata. Each later line records the complete output and observation for one request. The first repetition is warmup.

This pilot covers one GPU and concurrency one. No KV cache is implemented, and the candidate recomputes the causal local byte prefix during drafting. Three repetitions characterize timing repeatability. Six prompts do not determine a serving p95 or a task-quality distribution. A matched cached target, workload-level quality, and loaded serving latency remain separate gates.

## Stream replay

All three initial symbols in the sweep were spaces. A separate instrumented replay (`stream/stream_probe.py`) uses the same greedy candidates and widths 1, 4 and 8. At each verified host commit, it timestamps the first complete non-whitespace Unicode character, the fourth raw byte and the sixteenth raw byte. Decode with incomplete trailing UTF-8 ignored for this display-only measurement. These completion targets describe different user experiences. They are host-ready times, before any network transport. See `stream/stream.patch` for the complete delta from the measured fixed-width code. Run `python stream/check_stream.py` to verify and recompute the medians.

The visible-first variant uses ordinary target steps until the first complete non-whitespace character is ready, then switches to width 4. It repeats the byte-at-a-time control in the same process. This intervention targets display latency without changing model decisions. It uses the same three short prompts, fixed 40-symbol output, one warmup and three timed repeats. Results are exploratory, and the threshold may need a policy for outputs with lengthy leading whitespace in a real serving system.
